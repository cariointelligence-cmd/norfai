## A. User can now

Admin Search health shows live queue depth split into queued vs running, by job type, oldest live job, leftover child crawls, stale locks, workspaces and live searches. The worker tick records a snapshot (throttled to 15s unless pressure jumps) and retires leftover child crawl jobs globally before claiming work. A running search Face shows how many jobs are still queued or running on that run.

## B. V1 gaps fixed

- Admin health was a single integer of queued+running across all tenants, no type/age split, 15s poll
- Worker tick did not measure, log, persist, or act on depth
- Leftover child crawls were only pruned for the 4 latest runs of the 8 users the worker picked
- Stale running locks were only stolen inside processJobsFor for those same users
- A 6396-job search was invisible as "Queue depth 6396" with no oldest-age or type breakdown

## C. Sources that actually work

Unchanged. Queue monitoring is Nerve/Immune, not a new Sensor.
